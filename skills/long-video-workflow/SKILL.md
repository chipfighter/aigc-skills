# 长片分场制作

片子一长，镜头就多，没法和用户一镜一镜从头聊，也不适合一口气设计完再一次性生成：问题会堆到最后才暴露，改起来牵一发动全身。这个 skill 把制作分成先粗后细的几层：先定大方向，再定每场要表达什么，然后一段一段设计镜头、生成、接上前面看一遍，再做下一段。

## 分工

- **你负责设计和执行**：把每场细化成镜头、准备素材、写提示词、粗剪每段。镜头层由你按 storyboard-preview 和 video-prompt 的规则自主设计，不逐镜问用户。
- **用户在三个节点拍板**：大方向、每场要表达什么、每段做完接上前面后看的那一眼。要用户决定的事集中到这三个节点上问；其余按已定的方向自己判断，重要的补充简要说明。
- **拍板时让用户有东西可看。** 只给文字让用户想象，用户很难判断。一段接好的视频、几张预览图、一镜一行的镜头表，都比长篇描述好判断。
- **用户授权你全权做时**，三个节点由你自己定：照样写总纲和分场、照样每段接上前面检查、照样存档，只是不停下来等用户。做完把成片和每个节点的决定一起交给用户，用户可以从任何一个节点改起。花积分的生成仍按 video-prompt 的规则，先和用户定好预算。
  - 各 skill 里要等用户确认才做的事照做，按已采用处理，例如成功片段的留档。
  - 各 skill 里要停下来交给用户的地方（例如同一处连续失败），按它建议的替代做法自己处理，写进交付说明。
  - 各 skill 里留给用户判断的事（真人感、表情、气质、声音自不自然），你替不了用户。不要改成自己判通过；写进交付说明，说清你看到或测到了什么、哪些没有人看过或听过。让 AI 判断 AI 生成的画面像不像真的、只看频谱判断声音自不自然，正是最容易漏的地方。
- 用户随时可以打断、改主意。合作方式以本 skill 和用户最新的说法为准。

## 按片长决定用几层

- 只有一场：不用本 skill。
- 约 30 秒到 1 分钟：总纲和分场写成一页，逐段制作照常。一页里每场仍写出入场状态和怎么接下一场，各一行就够：相邻两场靠它接上。
- 1 分钟以上，或场次较多：完整走下面的流程。

## 各步骤调用哪些 skill

本 skill 只管分层和节奏，每一步具体怎么做在下面这些 skill 里。到了对应的步骤就正式调用，不要只读文件或只看链接：调用了，它的规则才在这一步生效。

- **定全局决定之前**：调用 [视频提示词](../video-prompt/SKILL.md) 和 [分镜预览](../storyboard-preview/SKILL.md)。参考方式（默认全能参考，什么时候用关键帧）、人物参考怎么准备、要不要遮脸、全片定什么视觉规则，规则都在这两份里；先定了再读，就会定错。这时调用是为了按它们的规则定全局决定、一次问完 storyboard-preview 第一步的问题，不在这一步出镜头表或写提示词。
- **每段设计和生成**：调用 storyboard-preview 出镜头表，video-prompt 准备素材、写提示词；要出图时再调用 [生图摄影](../image-prompt/SKILL.md) 和 [生图清单与核对](../image-spec-check/SKILL.md)。
- **进后期之前**：调用 [后期音效制作](../post-production-sound/SKILL.md)，按画面设计声音，不直接拿视频模型自带的声音了事。
- **按需要**：强情绪的戏调用 [真实情绪表演](../natural-emotional-performance/SKILL.md)；复杂运镜、走位或遮挡调用 [白模动画](../white-model-animation/SKILL.md)；对齐表达见 [AIGC 创作看片学习](../aigc-learning-skill/SKILL.md)。它们不是每个项目的必经步骤。

同一个对话里已经调用过的不用每段重新调用；换了对话要重新调用。

## 项目文件就是记忆

项目会做好几天、跨很多轮对话。能接着做下去，靠的是项目文件，不是对话记录或 memory。本 skill 只管三样：

```
总纲.md            大方向、全局决定、场次表
分场/S01_xxx.md     每场一个文件：表达、出入场状态、镜头表、状态
改动记录.md         每次改了什么、为什么、影响哪些场
```

其他文件按项目自己的结构和其他 skill 的规则放。

- **设计文档只留当前版。** 总纲和分场直接改原文，改动原因写进改动记录，一条几行。不留 v1、v2 并存，也不写"没写到的以上一版为准"，否则下一轮不知道该信哪份。旧版本靠下一条的存档找回。
- **每过一个节点留一个存档。** 项目一开始就在项目文件夹里建 git 仓库，文字文件进 git，图片、视频、音频写进 .gitignore。每过一个节点、每次返工前各提交一次，提交说明写清是哪个节点或为什么改。改坏了或改完后悔，可以整体退回到改之前。用户不用懂 git，说一句"退回到第三场确认那时"就行。
- **项目内容不写进 memory。** 场次、人物设定、镜头只写在项目文件里。memory 里留着旧设定，返工后会和文件打架。
- **项目单独一个文件夹，在这个文件夹里工作。** 上级目录和其他项目里的旧笔记、旧版 skill 备份不是本项目的规则：它们可能早就过时，和当前 skill 冲突时以当前 skill 和用户最新的说法为准。翻到还有用的经验，在交付说明里提一句，由用户决定要不要补进 skill。
- **每轮只读需要的。** 总纲每次都读，所以要短，一两页以内。再读当前场的文件、前一场的出场状态、后一场的入场状态和当前场用到的设定。其他场的镜头表、旧提示词默认不读，只在核对某个具体衔接或细节时去读那一处。
- **换对话前把状态写回文件。** 一场做完或做了较大改动后，在文件里写清做到哪、下一步做什么，再开新对话从文件接着做。对话拖得太长，被推翻的方案还留在里面，容易被带回来。

## 第一步：定大方向（节点一）

和用户聊清：

- 一句话讲什么，最后想让观众感受到什么。
- 给谁看、在哪里放：平台、横竖屏、大致片长。片长是预算，不是限制。
- 硬约束：平台时长上限、必须对上的音乐、必须念完的文本、必须出现的内容。
- 全局决定：整片统一的东西（画风、视频模型、参考方式、全片的视觉规则等），以及每段都会被问到的事（例如 storyboard-preview 第一步的问题）。在这里一次定好，之后每段沿用，不再重问。

用户说不清要做成什么样时，不要急着写分场。从一个具体时刻问起，或者给两三个具体方向让用户挑，每个方向用几句话说清怎么开头、停在哪里、观众会有什么感受。方向没定就往下做，后面每一层都会跟着改。

把上面这些写进总纲，再加一张场次表，一场一行：这场让观众知道什么、感受到什么，情绪从哪到哪，预估时长。用户确认后再往下。

## 第二步：分场（节点二）

每场一个文件，写：

- **表达**：这场让观众知道什么、感受到什么，在全片里起什么作用。
- **入场和出场状态**：人物在哪、什么情绪、穿什么、道具在谁手里、时间和光线。相邻两场靠它接上。
- **和下一场怎么接**：硬切、匹配剪辑、声音先进等。场与场之间的衔接在这里定，不留到镜头层各定各的。
- **预估时长。**
- **状态**：草稿、已确认、制作中、已完成、待复核。

这一层只写"表达什么"，不写机位和镜头数，给镜头设计留出空间。可以一次写完全部场给用户看，用户逐场或一起确认。用户确认的是表达；之后的镜头设计要偏离已确认的表达时，先提出来。

```
# S03 站台（状态：已确认）
表达：她明知这次分开就不会再见，却装作只是平常送别；观众要看出她在忍。
入场：傍晚，站台，两人并排等车，她手里拎着他的包。
出场：车开走，她还站在原处，包已经交出去，手空着。
接下一场：车门关上的声音先进，切到车厢里的他。
预估时长：约 30 秒
```

## 第三步：逐段设计和生成

"一段"按戏来分，通常是一场；一场很长时按情节拆开，几场都很短时可以合成一段。标准是做完能看出这件事有没有讲清楚。广告、MV 这类没有连续剧情的片子，按段落或音乐段落分。全权做时也一样：全片都要用的人物和场景参考图可以先准备好（只有某段才用到的角度和场景，到那段再做），视频按段提交，一段接上前面看完再交下一段；一次交完全部镜头，问题要到最后才看得到。

每段开做时，用一两句话复述本段要表达什么，连同这段准备怎么演（video-prompt 动笔前要说的演法）和这段要问用户的事，合成一条消息。本段的镜头沿用这个表达，不逐镜再问；只有某个镜头要偏离时单独提出。

然后按 storyboard-preview 出这段的镜头表，按 video-prompt 准备素材和提示词。从前一段**实际**的结尾接，不从计划接：生成出来的结尾可能和计划不一样。

生成前自己过一眼：把这段镜头一镜一行列出来，写进分场文件（一页版就写进那一页），看能看清人物脸的镜头够不够撑起本段的情绪，镜头长短是不是都差不多，本段最重要的一下落在哪个镜头，和前一段的结尾怎么接。有问题先改设计，再生成。花钱的生成按 video-prompt 的规则。

## 第四步：接上前面看（节点三）

一段的视频选好后，粗剪这一段，带上前一段结尾的几秒接起来给用户看；第一段就单看。给之前自己先看接点，明显的问题先说明。

- 本段的问题在本段改。
- 用户确认后，把本段**实际**的出场状态和实际时长写回分场文件，更新状态。
- 报一下累计时长和总纲预算差多少。

全部段做完，接起全片看一遍，再进后期。

## 时长当预算

总纲和分场里的时长都是预算。每个镜头多长由镜头设计按戏决定，最终在剪辑时定：生成的片段常常只用其中一部分。累计和预算差得多时告诉用户，由用户决定接受、压缩，还是从别的场匀时间。

只有硬约束才把时长当限制。要对音乐时，按音乐段落分场，镜头卡在音乐的节点上。

## 返工：先找问题在哪一层

用户对结果不满意时，先判断问题在哪一层，只改那一层：

- **方向**：全片想表达的东西变了。改总纲，逐场看哪些场的表达还成立，只重做不成立的。
- **场**：这场没讲清，或者情绪不对。改这场的分场文件，重新设计这场的镜头；出入场状态变了，检查相邻的场。
- **镜头**：某个镜头没拍好。只重做这个镜头，不动整场。

在问题所在的那一层解决，不往上推。上层改动后，受影响的场标"待复核"，不自动重做。先把已有素材看一遍，能剪出新意思的先复用，再决定要不要重新生成。

**做到一半想改前面定过的东西，先在当前段试。** 按新想法把当前这段做出来，接上前面看。用户看了确定要改，再决定要不要往前后推、推到哪几场；试完不想要，退回存档，前面做好的都不受影响。

**改动会超出当前这一段时，先列影响再动。** 不论用户说的是大改还是一个小想法，先用几句话说清：问题在哪一层；要改哪些场的表达或出入场状态；哪些已经做好的段和素材要重做，大概要重新花多少积分；哪些不受影响。用户确认后，先存档再改。每次返工在改动记录里写一条。

存档能退回的是文件和设计，已经花掉的积分退不回来。所以真正兜底的是每段做完就接上前面看：问题发现得早，最多重做一段。
