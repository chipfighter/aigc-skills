# 画线标注运镜路线

镜头要按顺序经过场景里的几样东西时（FPV 穿行、一镜到底的游览），可以在场景图的副本上画出摄影机路线，和原图一起作为参考附给视频模型。路线画在图上，提示词说明这张图怎么读。

**还没有验证。** 做法来自一位创作者在 libTV 上的演示（Seedance 2.x 全能参考，2026-11）。演示里每种做法只给出一条结果，而且画线版和纯文字版用的提示词也不一样，说不清镜头走对是因为画了线，还是因为换了提示词。能确定的只有一点：模型会读图上的线。提示词没说明这些线是什么时，红箭头被画进了成片。用户没要求时，不专门安排付费测试，见文末"怎么积累结论"。

## 什么时候用

画线介于文字和白模之间：比只写文字多给了每个节点在画面上的位置，又比白模省事得多，几分钟就能画好。线直接画在真实的场景图上，模型不用再把粗模和场景图对齐。标注图和原图的位置是一一对应的，但模型仍可能把路线读错，看片时照样要查。

- 路线要按顺序经过三处以上、彼此分得开的东西，只写文字时模型容易漏点、跳点或换顺序。
- 要求的精度是"先到哪样东西跟前，再到哪样"。线画在平面上，表达不了高度、离东西多远和速度，这些用文字写。要准确控制高度、遮挡和变速，人物同时还在走位，或者已经失败过，交给 [白模动画](../../white-model-animation/SKILL.md)。
- 路线要绕到东西背后、钻进画面里被挡住的地方，或者朝镜头方向往回走时，一张图上的线说不清楚，这种用文字写。绕着一个人环绕也属于这一类，因为人的背面在图上画不出来。
- 简单的推拉摇移，文字就够，不画。

## 怎么画

- 先有一张干净的场景图。在它的**副本**上画，尺寸和构图不变，原图保持不动。两张一起附上：原图提供空间、布局、光线和人物，标注图只提供路线。
- 路点 3–6 个，第一个是起点。路点放在要经过的东西上或紧挨着它，模型会读成"飞到这样东西跟前"。线从东西旁边绕过去，不要穿过人物的脸。
- 线要粗，颜色和场景里的东西都分得开，默认红色；场景里红色多时换青色或绿色，并在提示词里写明是什么颜色。每段中间一个箭头，终点一个大箭头，路点画带编号的圆点。
- 图上只画线、箭头和编号，不写字，字可能被画进画面（同 [构图小样](../../storyboard-preview/references/composition-sketch.md) 的标注规则）。
- 画好先给用户看路线，用户认可再交付提示词。

用 [draw_route.py](../scripts/draw_route.py) 画（需要 Python 和 Pillow）。先看场景图，按经过的顺序估出每个路点的位置。坐标可以全部写成 0–1 的比例，不必换算缩放后的像素。在 video-prompt 目录下运行：

```
python scripts/draw_route.py 场景图.png 场景图_路线.png "0.24,0.30 0.34,0.60 0.57,0.76 0.75,0.50 0.59,0.22"
```

场景里红色多时加 `--color cyan`。画完自己看一遍：编号顺序、箭头方向都对，线没有压住要看清的东西。

## 提示词怎么写

照常按 [复杂运镜](complex-camera.md)，先写完整路径，再写镜内节点。另外加上下面几条说明，用自己的话写，按镜头取舍：

- **每张图的用途**：原场景图决定人物、服装、空间布局和光线；标注图只表示摄影机的路线。
- **线怎么读**：红线是摄影机经过的路线，箭头是方向，编号是先后。从 1 号点依次经过每个编号，到最后一个点，不跳过，不回头。
- **先说标记是什么，再说不出现**：线、箭头和编号圆点是加在场景图副本上的摄影路线注记，不是场景里的东西；实景的样子看原图，视频里不出现这些注记，也不把它们变成光带、绳子、拖影一类的东西。演示里没写这一条时，箭头被画进了成片。Scenario 在分镜板上试过：只写"不要出现箭头"，三次都照样出现；先说明这些是导演画的规划记号、不是场景里的东西，才管用（个案，我们没验证过）。
- **一个镜头拍完，中间不剪。** Seedance 会自己切镜头，见 [模型易错点](model-pitfalls.md)。
- **节点按编号写**，例如"到 2 号点时贴近吊灯，灯罩占半个画面"。线表达不了的高度、距离、速度和每段用多久，也写在这里。
- 摄影机类型和视角（FPV、超广角、只往前不后退之类）按镜头需要写，不是必填。

交付时写清两张图的编号和用途。两张都当普通参考（全能参考），标注图不当首帧。用 libTV 时，两张都接进同一个视频节点作参考图。

## 看片时查

- 画面里有没有出现线、箭头、编号，或者由它们变成的东西；
- 镜头是不是按编号顺序经过每个点，有没有跳点、换顺序、中途回头；
- 有没有自己切镜头。

路线要抽连续帧看，方法见 [模型易错点](model-pitfalls.md) 末尾。

## 怎么积累结论

- 不单独测：在本来就要生成的镜头里加上标注图，记下路线有没有按编号走、标记有没有进画面，按 SKILL.md 的交付和反馈留档。
- 用户愿意测时做一组对照：同一张场景图、同一段提示词，画路线 A 和方向相反的路线 B，再加一组不附标注图，每组两条。A、B 两组走向明显相反，而且各自对得上编号，说明画线有用；三组走向差不多，说明起作用的是提示词和场景。
- 有了结论，先记在项目文件里，交付时向用户提出；用户同意后再更新本文件开头的说明。
